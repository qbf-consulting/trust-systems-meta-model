# TSMM v0.26.0: Decision Resolution Semantics

TSMM v0.26.0 adds two canonical semantic distinctions and generalizes an existing authority invariant after a bounded research review.

## Added

- **Decision-basis separation (TSMM-DR-02):** a changed decision does not imply an authority change; authority, evidence, policy, lifecycle, correction, and evaluation-context changes remain distinguishable causes.
- **Explicit resolution (TSMM-DR-03):** a material unresolved condition persists until an admissible material basis change occurs; workflow progression, repetition, peer agreement, or confidence do not silently resolve it.
- Canonical identifiers for `DecisionTransitionBasis` and `MaterialUnresolvedCondition`.
- Machine-readable decision-resolution model, schema, and falsification validation.

## Strengthened

TSMM-AAC-04 already established monotonic authority constraints. v0.26.0 generalizes this as **authority non-amplification (TSMM-DR-01)** across communication, endorsement, aggregation, projection, republication, and transformation. The named failure pattern **authority laundering** describes attempts to substitute influence, reputation, repetition, role, or unrelated authority for the authority required by an effect.

## Research provenance

The investigation was informed by a read-only review of the independent experimental project Protocol of Care for Agents and its Simulation 01 authority-discrimination work:

- https://github.com/JessHines360/protocol-of-care-for-agents
- https://github.com/JessHines360/protocol-of-care-for-agents/blob/main/BRIEF.md
- https://github.com/JessHines360/protocol-of-care-for-agents/blob/main/experiments/SIMULATION_01_RUNBOOK.md

TSMM does not adopt the upstream project's normative vocabulary and creates no dependency on it. No upstream repository content was modified.

## Compatibility

This is an additive Candidate Specification release. Existing TSMM concepts are not removed. Existing coordinated TSMS/TRQP pins are not rewritten; a later stack release must independently evaluate and pin v0.26.0 if it adopts these semantics.

## Validation

```bash
make candidate-check
```

The candidate gate includes dedicated falsification checks proving that peer pressure, repetition, reputation, and workflow progression do not constitute admissible resolution.

## Non-claims

This release does not define a moral ontology, agent refusal policy, A2A message type, portable TIS wire format, ARPA protocol extension, or assurance certification. Those remain separate authority boundaries.
