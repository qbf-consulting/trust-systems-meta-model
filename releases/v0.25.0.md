# TSMM v0.25.0: Action-Specific Authority and Lifecycle-Safe Governance

TSMM v0.25.0 consolidates the material canonical-semantic work completed after v0.24.0. The release strengthens how trust systems represent authority at the exact point of a material commitment, external semantic conformance, and collective-authority change without collapsing identity, signature, runtime success, or historical validity into current authorization.

## Added and strengthened

### Authority at commitment

TSMM now makes the following invariants explicit and machine-testable:

- authentication or identity is not authority;
- a general mandate is not authority for every exact action;
- a valid signature does not by itself establish a legitimate commitment;
- reputation and prior runtime success cannot expand authority;
- current scope, expiry, revocation state, required approvals, and evaluation time matter at the material transition;
- missing or indeterminate authority evidence cannot be promoted to PASS.

The release adds canonical semantic identifiers, relationships, documentation, and falsification cases supporting these rules.

### Composite and collective authority lifecycle

TSMM now models consequential change to collective authority independently of any particular threshold cryptosystem. The semantic pressure tests cover:

- member added or removed;
- threshold changed;
- exercise rule changed;
- collective authority suspended or revoked;
- previously issued authority evidence becoming stale or invalid for current authorization;
- historical verification remaining possible where governance permits it.

The key distinction is that evidence may remain historically authentic while no longer being sufficient to authorize a current action.

### External semantic conformance

TSMM now exposes bounded external conformance profiles with fail-safe dispositions. External implementations can declare a semantic profile and provide inspectable evidence without turning TSMM into a certification authority. Unknown semantics, unsupported versions, missing evidence, or non-current state cannot silently become conformance success.

## Cross-layer relationship

This release remains the canonical semantic layer of the Trust Systems Modelling Stack (TSMS):

- **TSMM** owns canonical trust-system meaning and invariants.
- **TIS** owns portable schemas, identifiers, evidence contracts, and serialization.
- **TGA** owns executable governance compositions, implementation patterns, and negative execution tests.

The post-v0.24.0 work was exercised across those independent authority boundaries, but this release does not transfer authority among repositories.

## Compatibility

v0.25.0 is an additive Candidate Specification release.

No stable core TSMM instance semantics are removed. Existing v0.24.0 consumers remain valid for the semantics they already use. Consumers adopting action-specific authority, external conformance profiles, or collective-authority lifecycle semantics must explicitly bind the new concepts and validation expectations.

A TSMS stack release may pin v0.25.0 only at an exact reviewed commit. Version labels alone do not imply cross-repository compatibility.

## Assurance evidence

The canonical repository gate is:

```bash
make candidate-check
```

The candidate gate validates schemas, examples, semantic registries and projections, authority-at-commitment cases, composite-authority lifecycle cases, conformance profiles, governance declarations, documentation, portfolio relationships, and publication integrity.

Material implementation tranches incorporated in this release include:

- external semantic conformance profiles;
- authority-at-commitment semantic normalization;
- composite-authority membership and threshold-change pressure tests;
- QBF stewardship and publication normalization.

## Limitations and non-claims

This release does not:

- certify an external implementation;
- establish principal authority that is absent from an underlying governance system;
- make a valid signature equivalent to authorization;
- guarantee compatibility with unreviewed TIS, TGA, or other repository state;
- prescribe a specific DID, VC, ZKP, threshold-signature, payment, or settlement mechanism;
- turn historical verification into current authorization; or
- transfer semantic, schema, implementation, or certification authority to another repository.

## Release relationship

v0.24.0 remains immutable historical release evidence. v0.25.0 supersedes it as the current TSMM Candidate Specification for new adoption and for the planned TSMS Stack 2026.2 successor baseline.
